`docs/operating-deploy.md` in that repository has the support table. It is short on purpose: files, and a process on
`$PORT`. What is tested is such a process, not Next.js. FCP-WEB-002 stays `partial` until a framework has been run.

Later work added the customer runtime. A release can run replicas from a pinned image, in Docker here, started before traffic moves,
replaced if they die, and stopped after a drain. `deploy_it` does this with real containers. A shell loop stands in for a server,
because that is what the base image has.

## Found by these tests

A release could name any upstream, so a route could lead to an address on our side of the network. Upstreams a customer names now go
through a check when they are named and a resolver that drops our addresses at every connection.
