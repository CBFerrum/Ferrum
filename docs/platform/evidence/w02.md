`resources_it` ran ten more times in a row with nothing else running, all passing. An earlier run failed once with a
resource left `deleting`, while it was being rebuilt alongside other work, and it has not come back. The assertion now
prints the operation if it does. I did not find the cause. That is a known unknown, not a fixed bug.

PostgreSQL providers ran against two real servers, with real roles, logins, sessions, copies and restores. Faults are
injected around the real provider, never instead of it. The object provider ran against an in-memory store through the
same trait: **it has not been run against S3 or anything that speaks it.**

## Found by these tests

- A hostile request could not use `tenant` in a resource call, and left no trace: it is now on the audit record of
  whoever tried.
- `automation::save` trusted its controller to check for an administrator. What it saves runs as the system, so the
  kernel now checks too.
