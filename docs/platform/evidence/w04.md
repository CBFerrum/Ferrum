The hostile build ran a script trying the docker socket, the host's root, writing the system, mounting, chroot, the
gateway, the host, Kubernetes, the metadata address, the internet and DNS. All 13 answered no, nothing reached a listener
on the host, and no credential was in its environment.

This proves the configuration. **A container is not a boundary against a kernel exploit**, so running strangers' builds
on shared hosts waits for a qualified runtime class (`BLOCK-SANDBOX-QUALIFICATION`). Colima hid one real fault: a build
running as a fixed uid could not write to a checkout on a Linux host. CI now runs this, and builds run as the owner of
their workspace, never as root.
