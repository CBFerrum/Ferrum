## Run for real

A debug server with the `cloud` feature, and `ferrum task cloud_controller` as a separate process, on a fresh database. Through the
HTTP API a person created a project and environments, and a resource request went from an intent to a real PostgreSQL database in
3 seconds, with nobody turning the controller. The console was read in a browser pane: projects, a project, an environment and an
operation by its address. The controller exited cleanly on a signal.

That run found what no test had: the manifest's colour was not `#rrggbb`, so the app was dropped from the App Manager with one line
in a log and `/cloud/` said nothing was installed. It is fixed, and nothing tests a manifest against the server's own parser yet.
Approvals were not clicked through, because production takes a second factor and that account had none.

## Restoring

`recovery_it` takes a real `pg_dump` with a payment waiting, lets it go out, restores with a real `pg_restore`, and starts a server on
that. The payment does not go out again. It waits among the dead events for someone to look, new work waits with it, and a person says
what they checked. Cut connections to a real witness show a region stopping before its time runs out, the other taking over, and the
first refusing to take the right back when the way is clear.
