# Decisions

Consequential choices for the platform program. The handoff's technology table is a set of candidates, not a
statement of what is installed: nothing here is qualified until its entry in the registry says so.

| # | Decision | Rejected, and why | Gate |
|---|---|---|---|
| D-01 | The management plane is one new app, `CBFerrum/ferrum-app-cloud`, compiled into the server behind a `cloud` feature. Code, Deploy, Access and Resources are modules in it, not services | One service per noun: nothing yet shows a security, availability or capacity boundary between them. In the platform's `crates/`: apps get their own repository, and only what several apps build on stays in the platform | The first boundary that needs a process of its own splits it |
| D-02 | Pure rules live in `ferrum-cloud-contract` in that repository: canonical digests, the policy decision, state machines, hostnames, provider contracts. No I/O | In the kernel: they serve one app. In the SDK: nothing outside this app needs them yet | Move to the SDK when a second consumer exists |
| D-03 | Reconcilers run as a separate process, `ferrum task cloud_controller`: the same image, its own deployment, service account and network policy. It holds provider credentials; API replicas do not | Kernel jobs on every replica: then every replica could reach the forge's administrator API and a container runtime. A separate image: more to build and sign for no isolation gain | |
| D-04 | Customer code never runs in the management plane or the controller. A sandbox gets one job: a short-lived token for its source, an upload area, and nothing else | A build step in the controller. Handing a runner a database connection | Stop-ship if violated |
| D-05 | Canonical digests are RFC 8785 JSON with SHA-256, in an envelope naming the schema and canonical version. Intents hold strings and integers only, so no float formatting can differ between languages | Per-service serializers: they drift. Hashing the request body: key order and whitespace are not intent | Test vectors shared with the TypeScript SDK |
| D-06 | Policy is a typed decision function: deny overrides, a missing mandatory attribute denies, and effective rights are an intersection. Its answer names the rule that decided | OPA or Cedar now: another runtime and language for about a dozen rules, and enforcement points need their own compiled form anyway | Revisit if customers write their own policies |
| D-07 | Operations are a table of this app, `cloud_operation`, with an idempotency scope, a request digest, a fenced lease and an `unresolved` state. They follow the ledger's design and do not replace it: physical intents stay in `ferrum-ops` | Using `op_command` for everything: a deployment and a charger start have different meanings. A generic job alone: jobs retry; an operation must stop at an ambiguous outcome | |
| D-08 | The forge is Forgejo, behind a `SourceProvider` contract, as a separate service with one writable instance per repository set. External Git is a second implementation of the same contract. It was Gitea until 3 November 2026: Forgejo keeps a quota per owner and refuses a push past it, which Gitea has no way to do and GitLab keeps for its paid editions ([references/cloud.md](../references/cloud.md)) | A Git engine of our own: out of scope. Gitea: no quota, so Cloud measured repositories by hand. GitLab: the repository size limit is Premium and Ultimate, and it runs as several services. Repositories on an S3 mount: no locking or POSIX semantics | Exact version and license in the bill of materials; [BLOCK-PROVIDER-CONTRACTS](../registry/blockers.yaml) for a managed offering |
| D-09 | Sandboxes sit behind a `Sandbox` contract. Development and CI use Docker with no network by default, a read-only root, all capabilities dropped and PID, memory and CPU limits. Production needs a qualified runtime class (gVisor or microVM) on nodes that run nothing else | A Docker socket in a build: a host takeover. Namespaces alone: not hostile-tenant isolation | Docker here proves the contract, not hostile isolation |
| D-10 | Artifacts are content-addressed, finalized by a trusted publisher that holds the signing key, and stored through the server's existing object store | A builder signing its own output. A mutable `latest` | Harbor for images when SSR needs an OCI registry |
| D-11 | Static sites are served by `ferrum-serve`, a small separate process that holds a signed route snapshot and immutable files. It never needs the management plane to answer a request | Serving from the API process: a management outage would take sites down, and customer HTML would sit beside the shell | CDN and WAF are a provider decision: BLOCK-EDGE-SERVICE-TIER |
| D-12 | Customer sites live on a separate registrable domain from the management plane, with one host per deployment | Sibling subdomains of the shell: same-site for cookies | Public-suffix registration waits on BLOCK-PRODUCTION-DOMAINS |
| D-13 | Workload identity is a short-lived token signed by the control plane, naming tenant, project, environment, job and audience, with a SPIFFE-shaped subject | SPIRE now: a heavy dependency before a cluster profile exists. Long-lived service keys | SPIRE can issue the same subject later |
| D-14 | Resources are `ResourceRequest`, `ResourceInstance` and `ResourceBinding`. The first providers are PostgreSQL by database and role, and objects. A provider is privileged code in the controller, never a marketplace plugin | A shared root DSN. Letting an app choose its own tenant scope | Timescale: BLOCK-TIMESCALE-LICENSE |
| D-15 | Live status is a committed event log read by a `pg_snapshot_xmin` horizon: a reader never passes a transaction still in flight, so a commit out of order cannot be skipped | An auto-increment cursor: a lower id can commit after a higher one. NOTIFY as a bus: it is only a hint | |
| D-16 | Connection ownership extends Operations and IoT Edge: a record with a generation, a final check at the send boundary, and a charging session domain in the Edge app above the ledger | A second command ledger. Addressing a server by number | Physical deployment waits on BLOCK-EV-HARDWARE |
| D-17 | Tracing is added with OpenTelemetry when a management path needs it, behind a feature, and metrics keep bounded labels | A tenant label on every metric: unbounded cardinality | |
| D-18 | This work does not merge itself. Each workstream is a reviewable branch and pull request; author, reviewer and release approver stay separate roles | An agent approving its own change | A person merges |
