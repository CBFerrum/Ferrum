## How Ferrum's Drive and Office are built

- **Short answer.** Ferrum has no office engine of its own. Drive keeps the files and decides who may touch them. To edit Word, Excel and PowerPoint files it hands them to Collabora Online, a separate server the operator runs, built on the LibreOffice core (`office/collabora-online/kit/Kit.cpp`). As an option it also loads three small editors that run only inside the browser (GridCraft, WordCraft, PdfCraft). Ferrum's own documents (`.fdoc`, the Docs app) use an editor Ferrum assembled itself: TipTap in the browser, Yjs to merge simultaneous typing, and Yjs's Rust port (`yrs`) on the server.
- **What serves files.** Drive is a native Rust app inside the Ferrum server (`src/lib.rs`). Folders, files, versions, shares, links, comments and activity are 12 record types in PostgreSQL with row-level security (`packages/drive/entities/drive.yaml`). The bytes go to the platform file store (an S3-compatible bucket or a local directory, `ferrum/docs/operations.md`) through `Kernel::store_file`, which scans them with ClamAV when the operator configures it (`src/files.rs`, `ferrum/crates/kernel/src/scan.rs`). Signed-in screens call `/api/app/drive/…`; public links and editor servers call `/api/site/{workspace}/drive/…` (`src/site.rs`). Each request is checked against the person's own space, team-folder membership and unexpired shares inherited from folders above (`src/acl.rs`, `src/tree.rs`); what a person may not see answers 404. File types come from the bytes, every save is a new version, and quotas hold under concurrent uploads (`tests/drive_it.rs`).
- **Online editing (Collabora, over WOPI).** WOPI is the standard by which an editor server asks a file host for a file; Drive is that host (`src/office.rs`). On Open, Drive reads the editor's `/hosting/discovery`, picks its page for the file's extension and returns it with a 10-hour token signed with the workspace's key and bound to workspace, file and person. The screen posts the token into an iframe (`ui/src/Drive.tsx` `EditPage`). Collabora then calls back: CheckFileInfo, GetFile, PutFile and the lock calls. Each save is a new Drive version, a 30-minute lock keeps others from overwriting, and when Collabora publishes a proof key Drive checks its RSA signature on every call. Operator settings: `FERRUM_OFFICE_URL`, `FERRUM_OFFICE_WOPI_URL`, optional `FERRUM_OFFICE_IPS` (the `office` service of `ferrum/deploy/docker-compose.yml`, on by default since 11 Nov 2026).
- **Who does what online.** Collabora does the editing, cursors, comments and track changes. Drive shows who is in the file, from Collabora's own messages, and turns the editor's Share, version-history and Close buttons into Drive's panels (`ui/src/wopi.ts`, `ui/src/Drive.tsx`). ONLYOFFICE Docs in WOPI mode is named in `src/office.rs` and the plans, but I found no test against it in either repository (not verified).
- **Browser editors (add-on `drive-editors`).** GridCraft (xlsx, csv, tsv), WordCraft (docx, odt, rtf) and PdfCraft (pdf) are Rust programs compiled to WebAssembly that draw on a canvas; the file never leaves the browser. Ferrum serves their official builds unmodified, pinned by SHA-256 (`ferrum/deploy/editors/builds.txt`), as static files from a small nginx image on an origin of its own, with a hundred-line relay page between Drive's screen and the editor (`ferrum/deploy/editors/relay.js`). Drive's screen downloads the file, hands the bytes over and saves what comes back as a new version with the person's rights, under the same lock as Collabora, so one person edits at a time and nobody co-edits (`ui/src/BrowserEdit.tsx`, `ferrum/docs/plan/browser-editors.md`). The add-on is a manifest with no code (`addons/editors/app.yaml`). Open prefers the online editor when one runs; on phones the browser editors sit under "Open with" (`ui/src/Drive.tsx` `defaultEditor`). DeckCraft (PowerPoint) is left out because it has no host bridge (none in `office/deckcraft/apps/deckcraft-web/src`).
- **Live documents (`.fdoc`).** No editor server. The browser runs TipTap on a Yjs document; the server keeps it with `yrs` in PostgreSQL over `/ws/docs/drive/{file}`, relays between server replicas, and writes a Drive version when the last editor leaves or every ten minutes (`src/docs.rs`, `ferrum/docs/plan/collaboration.md` C3). Comments, suggestions, images, offline typing, search by words and export to HTML, PDF, Word and text sit on top (`ferrum-app-docs/ui/src/LiveDoc.tsx`, `src/site.rs` `export`); agents create, read and append Markdown over MCP (`src/docs.rs`). Drive writes its own Office templates: Word through the platform's writer, Excel with `rust_xlsxwriter`, PowerPoint with `zip` (`Cargo.toml`, `src/templates.rs`).
- **Dependencies and licences**
  - Collabora Online (separate service, image `collabora/code`, the `office` service of `ferrum/deploy/docker-compose.yml`): MPL-2.0 (`office/collabora-online/COPYING`). Ferrum's docs call CODE a development edition and say production needs a subscription or a build from source (`ferrum/docs/operations.md`; not verified with Collabora). The reference is the 25.04 branch; Ferrum was checked against 26.04.
  - ONLYOFFICE Docs (optional, untested): the editor interface in the reference is AGPL-3.0 with extra terms; the server is not in the reference, so its licence is not verified.

  - TipTap (editor toolkit on ProseMirror), Yjs (the merge algorithm), y-protocols, lib0, y-tiptap: MIT (`ferrum/web/node_modules/*/package.json`). `yrs` 0.28.0: MIT, vendored with one fix (`ferrum/third_party/yrs/FERRUM.md`).

## What Ferrum has

- **Drive 0.11.1.** Personal spaces and team folders with quotas; versions and check-out; shares to people or roles (View, Comment, Edit, Manage) that folders pass down, with expiry; public and per-guest links with password, expiry and download caps; trash with retention, stars, recent, shared-with-me, search (names and the words of live documents); comments with mentions, presence, access requests, activity; five admin reports; Office templates; the intents `pick`, `preview`, `share` and a details panel for other apps (`app.yaml`, `packages/drive/README.md`). 54 actions on `DriveSpace` (`packages/drive/entities/drive.yaml`), all also over MCP (`packages/drive/README.md`).
- **Drive screens** (`ui/src`): `Drive.tsx` (list, New, Upload, tabs, search, row menu, editor page), `Details.tsx` (comments, versions, activity, request access), `Share.tsx`, `Templates.tsx`, `BrowserEdit.tsx`, `Pages.tsx` (viewer, picker, preview), `SharedLink.tsx` (guest page).
- **Office:** WOPI host, proof keys and locks in `src/office.rs`; Sheets, Slides and PDF as launcher entries (`app.yaml`); `ferrum/deploy/docker-compose.yml` (the `office` service), `ferrum/deploy/editors.yml`, `ferrum/deploy/editors/`.
- **Plans and spikes:** Collabora edited a Word file and saved a valid DOCX, and the stock image publishes no proof key until one is mounted (`ferrum/docs/plan/spike-s1-collabora.md`); GridCraft starts only on a real origin, not in Ferrum's opaque sandbox (`spike-s3-artcraft.md`); of 25 real files, 24 kept everything counted when opened and saved unchanged in the browser editors, a 5,000-table stress file did not open, and WordCraft and PdfCraft ignore `?chrome=none` (`browser-editors-fidelity.md`); the requests Ferrum made upstream are not met in these checkouts (`upstream-requests.md`).
- **Docs 0.5.2:** home with template gallery, recent, shared, starred, all and search by content (`ferrum-app-docs/ui/src/Docs.tsx`); editor with cursors, comment threads on text, suggestions, images, offline typing, Word and PDF export (`LiveDoc.tsx`, `CommentRail.tsx`, `suggest.ts`, `coedit.ts`); six seeded templates (`ferrum-app-docs/packages/docs/package.yaml`).
- **Defects seen by reading (not run):** (a) `ui/src/Drive.tsx` asks `list_folder` for 500 items, the server clamps to 200 (`src/ops.rs`, `page(50, 200)`) and the screen never pages, so a folder over 200 entries hides the rest; (b) New always opens the online editor (`Drive.tsx` `create`), so a workspace with only browser editors lands on "cannot be opened online"; (c) `ferrum/docs/plan/platform.md` §4.1 lists PutRelativeFile in the WOPI host, but `src/office.rs` has no handler for it.

## What Ferrum already does better

- **No third-party viewer.** Frappe Drive previews Office files by sending a link to Microsoft's viewer (`drive/frappe-drive/frontend/src/components/FileTypePreview/MSOfficePreview.vue`). Ferrum frames only servers the operator runs (the `csp.frame` list in `app.yaml`), and the browser editors may not make network requests (`connect-src 'self'`, `ferrum/docs/plan/browser-editors.md` §6).
- **Suggesting mode and Word export.** Live documents have a Suggesting mode, comments anchored to text that follows edits, and Word export with images, merged cells and suggestions as tracked changes (`ferrum-app-docs/ui/src/suggest.ts`, `ferrum/crates/kernel/src/coedit/docx.rs`). I found no suggesting mode in Outline's or Docmost's editors (the matches were menu plugins). Docmost's core exports HTML and Markdown only (`docs/docmost/apps/server/src/integrations/export/dto/export-dto.ts`); Outline's export formats include no Word (`docs/outline/shared/types/fileOperations.ts`).
- **Agents.** Drive and Docs actions, including create, read and append on live documents, are open over MCP under each person's rights (`packages/drive/README.md`, `ferrum-app-docs/packages/docs/README.md`). Docmost's MCP sits behind a licence check (`docs/docmost/apps/server/src/core/workspace/services/workspace.service.ts`; route `/settings/ai/mcp` in `referance/_inventory/docs__docmost.txt`); I found no MCP in Outline's server, app or plugins.
- **Strong, but not compared with the references (not verified):** a guarded editor host with proof-key checks, tokens bound to workspace, file, person and ten hours, one lock shared by the online and browser editors and a base-version check so a stale save becomes a conflict or a copy (`src/office.rs`, `ui/src/BrowserEdit.tsx`); access that fails closed, with one predicate for lists, search, breadcrumbs and shares, uniform 404s, hashed link tokens and a lockout after ten wrong passwords (`packages/drive/README.md`, `src/sharing.rs`, `tests/drive_it.rs`); malware scanning that refuses uploads when the scanner is down (`ferrum/crates/kernel/src/scan.rs`).

The ArtCraft name and logos are not open source and are allowed only in unmodified official builds; a modified build must remove them (`office/gridcraft/docs/brand/LICENSE-brand.txt`). Ferrum's unmodified, pinned builds with no ArtCraft name in its listing fit this.

Ferrum hosting for customers could fall under it: ideas only, no code.
- **Docmost:** core AGPL-3.0; everything under `apps/client/src/ee`, `apps/server/src/ee` and `packages/ee` needs a paid subscription in production (`docs/docmost/packages/ee/LICENSE`): AI, page permissions, templates, audit, SCIM, PDF export and docx import sit there, and MCP is licence-gated. Never reuse those.

Frappe Drive is archived (`drive/frappe-drive/README.md`).
- **Ferrum:** apps AGPL-3.0-only (`app.yaml`), platform crates AGPL-3.0-or-later (`ferrum/docs/licenses.md`).
