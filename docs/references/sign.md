# Sign: references

**Compared with:** documenso/documenso `503cd1aa1c75` (apps/remix, packages) and docusealco/docuseal `13a1835c006e` (app/, lib/) against ferrum-app-sign 0.1.0 (working tree, `691c67d`) and the records frame in ferrum (`81b7f7c`). **Date:** 2026-11-01

## What Ferrum has

- 7 entities (`SignRequest`, `SignTemplate`, `SignEvent`, `SignSettings` and the child rows `SignRequestSigner`, `SignField`, `SignTemplateRole`), 2 roles, 3 reports (`packages/sign/entities/sign.yaml`, `packages/sign/package.yaml`, `src/reports.rs`).
- Sequential or parallel routing by `signing_order`; six field types (Signature, Initials, Date Signed, Name, Text, Checkbox) per signer role, placed by page and x, y, width, height in points from the top-left of the displayed page and checked against the page geometry; reminders, expiry, correction of unsigned signers, void (`sign.yaml`, `src/document.rs`, `src/request.rs`, `src/upkeep.rs`).
- Public signing without an account: HMAC link tokens (expiring, single-use, constant-time), optional Argon2id access code with lockout, a self-contained signing page under a strict CSP, drawn or typed signature, consent, decline (`src/site.rs`, `src/signing.rs`, `src/token.rs`, `src/signature.rs`).
- Sealing: values stamped on the original pages, an audit certificate appended as an incremental update so the signed part is a byte prefix of the sealed file, SHA-256 kept, a public `POST /verify` for a presented PDF (`src/seal.rs`, `src/pdf.rs`, `src/site.rs`); an append-only hash-chained `SignEvent` trail with a `verify` action (`src/event.rs`).
- No PAdES and no qualified signature, by design: the sealed file carries no certificate signature a PDF reader can validate. `Cargo.toml` has `lopdf`, `sha2`, `hmac` and no CMS, X.509 or timestamp code; the certificate says so (`src/seal.rs`, `packages/sign/README.md`, FERRUM-SIGN-002 in `ferrum/docs/registry/apps.yaml`).
- In the records frame field placement is a grid of typed numbers, and the results of `send`, `verify` and `remind` are not shown (the frame only toasts "done": `ferrum/web/src/app/FormView.tsx` afterAction), so links go out by notification when Mail is absent (`packages/sign/README.md`). The document is shown in a native PDF iframe (`src/site.rs`). Read from code, not run.

Advanced and qualified levels (row 4) add a qualified trust service provider and identity checks of the signer, which is registry blocker `BLOCK-SIGNING-PROVIDER`.

## What Ferrum already does better

- A hash-chained, append-only trail: events carry `seq`, `prev_hash` and `event_hash`, a database trigger refuses updates, and `verify` recomputes the chain (`src/event.rs`, `SignEvent` in `sign.yaml`). The table definitions of Documenso (`DocumentAuditLog`, `packages/prisma/schema.prisma:531`) and DocuSeal (`submission_events`, `db/schema.rb:353`) have no hash or sequence column; hashes inside their `data` field: not verified.
- The sealed file can be checked without trusting the server: the certificate prints the SHA-256 and length of the signed prefix (`src/seal.rs`). This proves integrity only and is weaker evidence than the certificate signatures in rows 3 and 4.
- A request links to any record (`reference_entity`, `reference_id`) after a read check, and the platform's roles, audit and personal-data rules apply, including a stated reason for keeping evidence (`sign.yaml`, `personal_data` in `packages/sign/package.yaml`).
- The signing page loads nothing from elsewhere (CSP `default-src 'none'` with a nonce) and a signer receives only their own fields (`src/site.rs`, `src/signing.rs`).
- A trade-off, not a win: Ferrum keeps a salted hash of the signer's IP (`src/event.rs`), better for privacy; Documenso keeps the address (`ipAddress` in `DocumentAuditLog`), better as evidence.
